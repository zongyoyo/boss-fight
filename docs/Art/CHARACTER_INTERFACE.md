# 角色接口規格

Oct 30, 2026 · Phase 0 產出（量測自 `claude/prologue-fixes` alpha-3.0.0 的 prefab 與程式）

換角色模型時「不能動的東西」都在這裡：碰撞與判定尺寸、程式會轉動或縮放的節點（pivot）、錨點，以及程式對材質的要求。造型、色格、面數照 `ART_STYLE.md`；草稿在 `Art/草圖/<角色>/`。第 8 節是草稿與企劃書不一致、要你決定的事項。

座標一律是 **prefab 根物件空間**（+Z 前方、+Y 上、1 = 1 m），角度是 Unity 的 Euler（度）。

## 1. 共通規則

### 1.1 程式怎麼找到部件

- 執行期**不用名字找部件**：Poser／Animator／Visual 的欄位都是 Builder 用 `SerializedObject` 接好的引用。名字的作用是讓 Builder 重建時找得到要接的節點，所以 pivot 名稱照本文件，Builder 改成從 `ArtLibrary` 掛模型時照名字接線。
- 例外只有「整批收集」的程式，它們會抓到模型底下**所有**的 Renderer／MeshFilter，模型裡不能藏不該被它們處理的東西：

| 程式 | 收集什麼 | 對模型的要求 |
| --- | --- | --- |
| `DaoDunDogAnimator` | 角色底下所有 Renderer（受擊無敵閃爍） | 無 |
| `BossPhaseVisual`（OIIA 二階段殘影） | `Model` 底下所有 MeshFilter，用 ghost 材質畫 | 只畫第一個 submesh：一個部件一個材質，多材質的部件拆成兩個物件 |
| `BossTelegraphFlash`、`TrainingSaplingVisual` | Builder 列進 `renderers` 的清單 | 新部件要列進清單（Builder 依 Model 底下的 Renderer 列） |

### 1.2 Pivot 保留、網格換掉（建議的換法）

現在的程序動畫數值（揮刀關鍵姿勢、坐姿角度、爪子座標）都是對著現有 pivot 的位置與靜止角度調的。最省事又不會歪的換法：

1. Builder 照舊建立 pivot 空物件（位置、靜止旋轉、縮放都跟下表一樣）。
2. 每個模型部件在 Blender 以 **Model 空間、不旋轉** 建模，物件原點放在它所屬 pivot 的位置（下表的「pivot 位置」）。
3. Builder 把部件放到 Model 空間的那個位置後，再掛到 pivot 底下並**保持世界座標**（`SetParent(pivot, true)`）。這樣 pivot 的靜止旋轉（例如刀盾狗 `Arm_R` 的 (310, 0, 12)）與縮放（刀的 1.3、菊花與小樹精 `Model` 的 2）都不用改，程式的數值照舊有效。

部件的原點與 pivot 位置誤差要在 1 cm 內（自動檢查第 3 項），否則轉動時會偏心。

### 1.3 材質

- 閃白、預兆閃光、小樹精的發光都用 `MaterialPropertyBlock` 寫 `_EmissionColor`。所以 **`M_Palette` 必須開 Emission、不接 Emission Map、`_EmissionColor` 預設黑**：接了 emission 貼圖的話，黑色區域乘出來還是黑，閃光就看不見。發光色格（色票第 12–13 列）只給 `M_Palette_Emissive` 用。
- 大樹守衛的樹冠與裂縫、OIIA 幻影用 `_BaseColor` 換色：這些部件用獨立的純色材質（不接色票貼圖），否則換色會被色票的顏色乘掉。
- 獨立材質槽的部件做成**獨立物件**（不要做成同一個網格的第二個 submesh），理由見 1.1 的殘影。

### 1.4 尺寸

- 碰撞體與判定（Hurtbox、CharacterController、實心 Collider）不改：新模型照下表的尺寸做，視覺比例要和它們對得上（誤差 5% 內）。
- 新模型的視覺包圍盒以「現有視覺包圍盒」為目標；要明顯放大或縮小（例如村長，見第 8 節）時先問。

## 8. 草稿對照與待決事項

草稿整體方向（低面數、平面著色、可愛圓胖）和計畫一致。下面是草稿和企劃書或現有程式對不上的地方，照 CLAUDE.md「先問、不自行改規格」列出，開工那個角色前要先定。
