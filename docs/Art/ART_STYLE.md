# 低面數美術改造計畫

Oct 30, 2026 · @Zucknight

## 目標與風格解讀

目標是把所有佔位幾何換成「平面著色＋色票貼圖」的低面數模型：場景直接取 How to Fish 的語言，角色沿用同一套渲染規則，但造型自己設計。現有 Builder 拼出來的形體全部可以丟掉，只保留它們的**位置、尺寸與程式接口**（掛點、骨節名稱、碰撞體）。

從兩張附圖拆出來的規則：

| 附圖特徵 | 在圖裡看到的 | 轉成我們的規則 |
| --- | --- | --- |
| 平面著色 | 每個面一個明暗，邊緣是硬的 | 全部 flat shading，不做平滑法線 |
| 色塊為主 | 木牆、屋頂、草都是純色，幾乎沒有紋理 | 共用一張色票貼圖，細節不靠貼圖 |
| 細節用幾何 | 木板一片一片分開、窗框有分格、門是拼板 | 看得出結構，但不做倒角、不做小於 3 cm 的細節 |
| 輕微不規則 | 樹幹、石頭、草葉都有點歪 | 頂點隨機偏移 2–5%，不用完美的圓柱和方塊 |
| 植被量大 | 前景大量細長草叢、層疊鋸齒狀的針葉、枯枝 | 植被套件要做足變體，靠散佈填滿畫面 |
| 光影決定質感 | 暖色主光、清楚的投影、偏藍的陰影、遠處泛霧 | 光照與後處理和模型一樣重要（第 3 節） |

一句話版本：**形體簡單但結構誠實，顏色平但光影豐富。** 這也剛好是 Claude Code 用 Python 腳本最擅長做的範圍。

## 風格規範（Style Bible）

規範要寫成數字，因為 Claude Code 每次開工都要能照著做、照著檢查。整份計畫存成 repo 裡的 `docs/Art/ART_STYLE.md`，`CLAUDE.md` 指向它；這一節是每個資產開工前必讀、收尾時逐條檢查的部分。

### 形狀

- 圓柱 6–8 邊（樹幹、柱子），大型物件最多 10 邊；球用 icosphere 細分 1 次，主角頭部最多 2 次。
- 不做倒角。邊緣靠相鄰面的明暗差來表現。
- 頂點隨機偏移：自然物 3–5%，人造物 1–2%（木板要直，但不能完美）。
- 剪影優先：在遊戲鏡頭距離下，剪影要一眼認得是什麼。
- 最小細節 3 cm，比這更小的就省略或併進大形。

### 著色與顏色

- 全部 flat shading，匯出前三角化，避免 Unity 重算法線。
- 共用色票貼圖 `T_Palette.png`：256×256，16×16 格、每格 16 px；Unity 端 Point 濾鏡、關 mipmap、不壓縮。
- UV 不展開：每個面的 UV 縮到它所屬色格的中心點。上色就等於「選面、指定色格」。
- 色格分區：第 0–3 列自然物、4–7 列人造物、8–11 列角色、12–13 列發光色（對應同座標的 emission 貼圖）、14 列是自然物的補充（0–3 列已滿：雪）、15 列保留。
- 每個顏色做亮／中／暗 3 階；物件底部與凹處用暗階，模擬附圖裡的面明暗變化。
- 換色變體（測試狗）用第二張色票，座標相同、顏色不同，材質只換貼圖。
- 戰鬥中要變色或發光的部位用**獨立材質槽**，不走共用色票：大樹守衛的葉子與裂縫、OIIA 貓項圈、傳送門符文、營火與爐火。
- 之後若覺得太平，再把木頭、石頭的色格換成帶細微雜訊的小區塊，UV 展到格內（附圖第二張的木牆就有這種顆粒）。第一版先不做。

### 比例、方向與軸心

- 1 Blender 單位 = 1 m。Unity 端用現有的 `ScaleRef_2m` 對照。
- 換模型前先量現有 prefab 的包圍盒（Phase 0 做），新模型以這些尺寸為準，不動玩法尺寸與碰撞。
- 模型正面朝 Blender −Y，匯出後在 Unity 朝 +Z（Phase 0 用測試方塊驗證一次）。
- 地面物件的軸心在底部中心；角色每個部件的軸心在關節上（耳根、肩、髖、尾根、莖底）。

| 大型 Boss | 3,000–6,000 | 大樹守衛 |
| 次要角色 | 500–1,500 | 菊花老師、小樹精、村長 |
| 建築 | 800–2,500 | 村長小屋、鐵匠鋪 |
| 中型道具 | 100–600 | 鐵砧、營火、圓木座椅、傳送門 |

### 命名

- 靜態網格 `SM_<類別>_<名稱>_<變體>`（例：`SM_Tree_Pine_A`）；角色 `CH_<名稱>`。
- 角色部件名稱沿用現有 prefab 的層級名（`Head`、`Ear_L`…），Builder 靠這些名字找到 pivot 接線（執行期不用名字找，細節見 `docs/Art/CHARACTER_INTERFACE.md`）。
- Blender 物件名就是 Unity 物件名，匯出後不再改名。
- 材質：`M_Palette`、`M_Palette_Emissive`、雙面的 `M_Palette_Foliage`（草、葉片這類單片網格），其餘特殊材質保留原名。

## 光照與後處理

附圖的質感有一半來自光照：同一個平面著色模型，放在平光下會很廉價，放在暖色斜光加藍色陰影下才會像 How to Fish。這一節在 Phase 1 風格切片時定案，三個場景共用一份基礎 Volume Profile（`Assets/Art/Settings/VP_LowPolyBase.asset`），各場景只覆寫天空、霧色與主光角度。

Phase 1 實際用的值（序章）：主光 #FFF0D8、強度 1.3、仰角 42°；陰影沿用 PC_RPAsset（Soft、4 級、50 m）；SSAO 沿用 PC_Renderer（0.4、半徑 0.3）；三色漸層天空（天頂藍、地平線 = 霧色、地平線以下灰綠，主光方向一圈柔光）；Trilight 環境光；指數平方霧 0.006；基礎後處理是 Neutral、對比 +10、飽和 +10、Split Toning（亮部 #998A6B、暗部 #6B7F9E）、Bloom 0.3／門檻 1.1、Vignette 0.2。

| 項目 | 設定起點 | 目的 |
| --- | --- | --- |
| 主光 Directional | 暖白（約 #FFF0D8），強度 1.2–1.5，仰角 35–50° | 斜光讓每個面明暗分明 |
| 陰影 | Soft Shadows，2–4 級 cascade，距離 50–80 m | 附圖的投影清楚是重點 |
| 環境光 | Gradient：天空藍、地平線淺灰綠、地面暗棕綠 | 陰影面偏藍，不會死黑 |
| SSAO | URP Renderer Feature，強度 0.3–0.6，半徑小 | 草叢根部、木板接縫有暗角 |
| 霧 | 指數霧，顏色取天空地平線色 | 遠景退後，畫面有深度 |
| 天空 | 兩色或三色漸層天空盒，取代佔位天空 | 漸層最符合低面數風格 |
| 色調映射 | Neutral | 不讓色票顏色被偏色 |
| Color Adjustments | 對比 +5–15、飽和 +5–15 | 附圖顏色鮮但不刺眼 |
| Split Toning | 亮部偏暖、暗部偏藍 | 暖光藍影是附圖的主色調 |
| Bloom | 低強度、高門檻 | 只讓火、符文、雷、裂縫發光 |
| Vignette | 0.15–0.25 | 收邊 |
| 材質 | `M_Palette` Smoothness 0、Metallic 0 | 全霧面，避免塑膠反光 |

各場景的氣氛：序章是晴朗午後（改寫現有的 `AfternoonVolume`），休息區是偏黃昏的暖光、營火是主要點光源，競技場是風雨交加的黑暗森林，冷色月光加閃電照明，設定見第 8 節。

## 工具分工與管線

主線是「Claude Code 寫 Blender Python 腳本 → 透過 Blender MCP 執行 → 匯出 FBX → Unity 的 Builder 換掛模型」。腳本就是模型的原始碼，和現有 Builder 的精神一樣：可重跑、可用亂數種子做變體、可以 review 差異。

### 工具分工

| 誰 | 負責 | 不負責 |
| --- | --- | --- |
| Claude Code + Blender MCP | 全部環境、建築、道具、特效網格；角色的組裝、上色、拆件、匯出 | 有機曲面的精細造型 |
| 本地 Hunyuan3D | 有機角色的**體積參考**（貓、狗的身體，守衛樹幹的臉） | 直接進遊戲：減面後是雜亂三角形，和刻意的低面數不搭 |
| 你 | 每個角色的正面＋側面草稿（手繪即可）、各驗收關卡、Blender 裡的小修 | 重複性的建模工作 |
| Claude Code（Unity 端） | 改 Builder、換掛模型、碰撞體、材質、植被散佈 | 美術判斷 |

Hunyuan3D 的參考網格怎麼用：放進 Blender 的 `REF` collection，半透明顯示。身體、頭這類圓胖形體，用低細分的 icosphere 加 Shrinkwrap 貼到參考網格上，再平面著色，就能得到乾淨的低面數拓撲；耳朵、爪子、尾巴這類小件直接用腳本建。

### Blender 端規則

- 每支資產腳本都能重跑：先清掉自己的 collection 再重建，結果只由腳本和亂數種子決定。
- 長腳本存成檔案，經 MCP 執行（寫法見 `Art/Blender/README.md`），不要把幾百行程式碼塞進對話。每個資產有自己的 Blender scene（同名），互不干擾。
- 建模用 `bmesh` 與資料 API，少用 `bpy.ops`（ops 依賴編輯器狀態，最容易莫名失敗）。
- 匯出統一走 `export_fbx(objs, relpath)`：只匯出該資產、套用修改器、三角化、Forward −Z／Up Y、在 Blender 端烤進座標軸轉換（Apply Transform）。物件的旋轉與縮放要先歸零（`apply_rotation_scale`），`check` 會擋。
- 共用形體：`add_box`、`add_prism`（柱、錐台、尖錐）、`add_icosphere`（細分 1 次 = 80 面）、`add_rock`、`add_plank`、`add_tube`（沿折線的管子：彎樹幹、樹枝、樹根，半徑 0 收成尖）。上色可以在建模當下用 `shade_faces(bm, faces, 組名)` 依面的朝向分亮／中／暗（只處理那個部件的面），或事後用 `paint`／`shade_by_normal`／`shade_by_height`。
- 同類資產一支腳本、變體寫在腳本的 `VARIANTS`（例：`assets/env/SM_Tree_Pine.py` 的 A），一次產生全部變體。
- 色格存在網格的 int 面屬性 `cell`，`finalize` 時才把 UV 縮到色格中心、依色格分到 `M_Palette` 或 `M_Palette_Emissive` 槽；不走色票的獨立材質用 `finalize(obj, material="名稱")`，名稱就是 Unity 材質資產的名稱。

### Unity 端規則

- 匯入設定由 `Scripts/Editor/ArtImportPostprocessor` 自動套用（取代手動的 Preset，使用者同意的做法）：
  - `Assets/Art/Textures`：Point 濾鏡、無 mipmap、不壓縮、Clamp。
  - `Assets/Art/Models` 的 FBX：Scale Factor 1、Normals = Import、不要切線、Animation Type = None、Read/Write 關、不加碰撞體、不烤 Bake Axis Conversion。
  - 材質**依名稱對應**（使用者同意，取代「Materials = None、由 Builder 指派」）：匯入後把每個材質換成專案裡同名的材質資產（先找 `Assets/Art/Materials`，再找 `Assets/Models` 的獨立材質槽，例如 `OiiaCat_Collar`）；找不到時 Console 警告。FBX 裡會留一份沒人用的內嵌材質（Unity 在內嵌模式不呼叫 OnAssignMaterialModel，只能匯入後再換）。
- 軸向修正只在 Blender 端做（Apply Transform），Unity 不開 Bake Axis Conversion。Phase 0 的 `SM_Test_AxisCube` 驗證過：Rotation 0、Scale 1、高 1 m、Blender −Y 的正面在 Unity 朝 +Z、模型自己的右手邊（Blender −X）在 Unity +X（沒有鏡像），每個面的法線分開（硬邊）。
- `M_Palette`：URP Lit、Smoothness 0、Metallic 0、GPU Instancing，開 Emission 但不接 emission 貼圖、顏色黑（閃白與預兆閃光才有作用）；`M_Palette_Emissive` 多接 `T_Palette_Emissive`、Emission 白；`M_Palette_Foliage` 同 `M_Palette` 但雙面（Render Face Both），草叢的法線在 Blender 端用 `normals_up` 全部朝上，正反面一樣亮、光照跟地面一致（`finalize(obj, base_material=MAT_FOLIAGE)`）。由 Tools > Art > Setup Art Assets 建立（只在不存在時建，之後在資產調）。
- `ArtLibrary`（`Scripts/Editor`，只給 Builder 用；資產在 `ScriptableObjects/Art/ArtLibrary.asset`）：id 是 FBX 檔名，`Assets/Art/Models` 有變動時自動同步。Builder 原本建基本形體的地方改成 `ArtLibrary.Spawn(id, parent, fallback)`：有模型就放模型（保留 prefab 連結），沒有就呼叫 fallback 建原本的佔位幾何。換模型可以一件一件來，遊戲隨時都能跑。
- 選單 Tools > Art：Setup Art Assets（建資料夾與材質、套匯入設定、同步清單、重新匯入 FBX，最後跑檢查）、Sync Art Library、Validate Art（色票貼圖與材質設定、每個 FBX 的匯入設定、節點的旋轉與縮放、材質都換成了專案資產）、Place Axis Test（在目前場景放測試方塊，EditorOnly）。
- 碰撞體與玩法層級（`ArenaWall` 等）仍由 Builder 用簡單碰撞體建立，不用 Mesh Collider。
- 光照與後處理（Phase 1 定案的做法，數值見「光照與後處理」）：每個場景兩層全域 Volume，`BaseVolume`（優先度 0，共用 `VP_LowPolyBase`）與場景自己的覆寫（序章是 `AfternoonVolume`，優先度 1，目前是空的）。演出要壓暗或改色時，不要用固定值覆寫基礎設定，改成另一層 Volume、用權重從基礎值漸變過去（序章的 `PrologueCinematicStage` 就是這樣做）。序章的主光、天空、環境光、霧都在 `PrologueLayoutData`，Tools > Prologue > Apply Atmosphere 套到場景（原地更新主光，不重建）。
- 現有程序網格（`Arena_*`、`Hub_Cone`…）只在 fallback 時才重建，不再覆寫正式模型。

## 單一資產的工作循環

每個資產走同一個循環：一個資產（或一組同類套件）開一個 Claude Code session，做完就 commit。

1. **讀規格**：`ART_STYLE.md`、該資產的建模卡（第 7–9 節）、角色另讀接口規格 `docs/Art/CHARACTER_INTERFACE.md`（Phase 0 產出）與 `Art/草圖/<角色>/` 的草稿。
2. **Blockout**：寫 `Art/Blender/assets/<類別>/<名稱>.py`，只建大形、不上色。
3. **看剪影**：出一張四視角合成圖（正、側、背、3/4），旁邊放 2 m 比例尺與現有佔位物的包圍盒線框。比例或剪影不對就回到第 2 步。
4. **細節與上色**：加結構細節、指定色格。
5. **自動檢查**，腳本印出結果：
   - 三角面數在預算內
   - 全部 flat shading、所有 UV 都落在色格中心
   - 軸心位置、物件名稱與接口規格一致
   - 沒有散落頂點，法線朝外
   - 尺寸與舊包圍盒誤差在 5% 內（角色、碰撞相關物件）
6. **姿勢檢查**（角色才有）：照接口規格的關鍵姿勢轉動部件，出一張姿勢合成圖，確認關節轉動時不露縫。部件之間要像玩偶的球關節一樣互相插入一點。
7. **你驗收**：主要角色、建築、風格切片一定要你看；石頭、草這類套件 Claude 自己判斷即可。
8. **進遊戲**：匯出 FBX → 登錄 `ArtLibrary` → 用正式光照在遊戲鏡頭截圖 → commit。

### 控制 token 用量

- 一律用**一張合成圖**驗證，不分開截四張；寬 1024 px 就夠。
- 先過剪影再做細節，避免細節做完才發現比例錯。
- 腳本存檔案、執行後只回傳摘要（面數、檢查結果），不把整個場景資訊印回對話。
- 同類資產一支腳本加參數一次產生多個變體（樹 4 種、石頭 6 種），一個 session 做完一整組。
- 同一個問題迭代 3 次還不對就停：改由你在 Blender 手動調整，或補一張更清楚的草稿，不讓 Claude 無限重試。

## 建模目標：角色與 Boss

角色保留「剛體部件」架構：每個會動的部位是獨立網格，軸心在關節，名稱沿用現有層級，所以 `OiiaCatPoser`、`DaoDunDogAnimator`、`GuardianPoser` 不用重寫。不做骨架與蒙皮，因為現在的程序動畫用不到，而綁骨刷權重也是腳本最難做好的部分。角色不抄 How to Fish 的造型，只共用它的渲染規則。

共通規則：

- 不會動的小部件併進大部件，主角部件數控制在 15–25 個。
- 花紋、眼睛、鼻子用「選面指定色格」或內縮面表現，不用貼圖。
- 頭暈星星統一成一個 `SM_DizzyStar`（五角星擠出，約 20 面），貓、守衛、小樹精共用，取代 `SaplingStar`。
- 每個主要角色開工前，你先給一張正面＋側面草稿。

### OIIA 貓（主 Boss，Phase 3，角色管線的試做）

- **造型**：圓胖的豆形身體（不再是膠囊），頭身相連；大三角耳分外耳、內耳兩色；眼睛是內縮面片加眼白與瞳孔；小鼻；雙爪是圓胖的肉球手。建議加一條尾巴（獨立部件，軸心在尾根），旋轉時剪影更好認，Poser 不控制它就固定不動。
- **花紋**：條紋用選面指定深色格畫上去。
- **面數**：1,500–2,500。
- **接口**：身體、耳、爪、項圈、星星沿用 Poser 找的名稱與軸心；旋轉軸在身體底部中心；倒地時耳朵與爪子不能穿進地面。
- **材質**：毛與深色部位走色票；項圈獨立材質槽（幻影分身時發光）。
- **幻影版**：身體、耳、爪三件直接重用，換 `OiiaCat_Ghost` 材質，不另做模型。
- **驗收**：遊戲鏡頭距離下，舉爪、伏低、旋轉、倒地四個姿勢剪影都清楚，旋轉中也看得出是貓。

### 刀盾狗（玩家，Phase 4）

- **造型**：圓頭、大口鼻、短腿胖身體、尾巴；耳形沿用現有設定。眼、眉、鼻用內縮面與色格。
- **部件**：從 74 個降到約 20 個。腳趾併進腳，鬍鬚改成口鼻上的色格；眼皮只有在 Animator 會眨眼時才保留獨立。
- **刀**：單刃寬刀，刀身＋護手＋刀柄，60–150 面。
- **盾**（上平下尖的騎士盾，和現有 prefab 與草稿一致）：盾面＋盾緣＋6 邊小凸起的鉚釘；太陽紋做成盾面上內縮的金色面，不再用一堆小物件；200–500 面。
- **骨頭**：`SM_Bone`，30–80 面，菊花老師丟的骨頭共用這個。
- **面數**：身體 1,500–2,200；刀、盾、骨頭合計 600 以內。
- **接口**：`PlayerRig` 的鏡頭跟隨點、臉部錨點、刀／盾／骨頭掛點全部同名同位置；營火坐姿要檢查腿與尾巴不穿模。
- **測試狗**：同一個 FBX，材質換成第二張色票（灰藍毛、暗紅盾面）。
- **驗收**：從玩家鏡頭（背後偏上）看，刀與盾的剪影清楚，盾面太陽紋可辨認。

### 大樹守衛（序章 Boss，Phase 5）

- **造型**：粗壯樹幹當身體，樹皮用縱向稜面表現；臉是樹幹上的凹洞，眼睛藏在洞裡；樹冠是 3 團多面體葉叢（中央＋兩側），延續環境樹的造型語言但更大。4 根樹枝當手、8 條樹根、4 條藤蔓。
- **面數**：3,000–6,000。
- **拆件**：樹根、樹枝、藤蔓、樹冠各自獨立，軸心在與樹幹的接點；8 條裂縫是貼在樹幹表面的薄片，用獨立發光材質（二階段亮起）。
- **換色**：樹冠用獨立材質槽，一階段綠、二階段紅（沿用 `LeafGreen`／`LeafRed`）。
- **參考**：可用 Hunyuan3D 生一棵「有臉的樹」，只取樹幹與臉部的體積。
- **驗收**：站在序章森林裡明顯比一般樹大、一眼看出是敵人；萬根齊發時樹根從底部伸出不露縫。

### 序章（Phase 2 換森林，Phase 5 做演出道具）

Phase 2 的做法（`Scripts/Editor/PrologueSceneryBuilder`，Build Prologue 會呼叫，只改佈景跑 Tools > Prologue > Build Scenery；參數在 `PrologueLayoutData` 的「佈景」）：

- 森林前 3 排的位置與樹幹碰撞照舊；離牆內緣 3 m 以內的樹只用樹冠高的闊葉樹與枯樹（隱形牆把鏡頭擋在牆邊，針葉樹的低枝片會把鏡頭包住）；牆外再種 4 排沒有碰撞的裝飾樹。

- 遠山：3 種山形，山肩外鼓、峰頂圓鈍（試過拉高成尖錐，太尖），峰高 70% 以上是雪（色票 `snow`，雪線每個面隨機上下）；放在半徑 60 m（比最外排裝飾樹遠一個山腳，樹不會插進山坡），高度約 22–36 m（`mountainScale`、`mountainHeight`）。

#### 天氣與光照

黑暗只能是氣氛，不能讓玩家看不清招式：環境暗、戰鬥元素亮。這一組設定覆寫第 3 節的基礎值。

| 項目 | 設定起點 | 目的 |
| --- | --- | --- |
| 主光 | 冷藍月光（約 #A9C4E8），強度 0.4–0.6，仰角 60–70° | 從上方打亮空地，四周樹林自然變暗 |
| 環境光 | Gradient 偏藍灰，整體調暗 | 陰影仍看得出形體，不會死黑 |
| 霧 | 指數霧，深藍灰，比其他場景濃 | 遠林只剩剪影，邊界消失在霧裡 |
| 天空 | 深灰藍漸層，加上緩慢移動的低面數雲層 | 和雷雲同一套造型 |
| 閃電照明 | 每 6–15 秒隨機一次，主光與天空瞬間提亮 0.1–0.2 秒，1–2 秒後接雷聲 | 週期性看清整片森林，也是氣氛的高點 |
| 雨 | 細長雨絲粒子 1,000–3,000 顆，跟著鏡頭；地面濺起小水環 | 雨是畫面的主體之一 |
| 風 | 樹冠與草的風擺 Shader，風力比其他場景強，偶有陣風 | 讓「風雨交加」動起來 |
| 地面霧 | 低矮的半透明霧片繞場邊緩慢飄動（取代開場的 `Smoke`） | 遮住圍圈底部，增加深度 |
| 濕地面 | `M_Palette_Wet`：同一張色票，Smoothness 0.5–0.6，只給地板、石頭、樹根 | 閃電與月光在平面上反出一塊塊亮面 |
| 色調 | 冷色為主，飽和度降 10–20；暖色只留給魔法陣、項圈、火花 | Boss 與特效在冷色環境裡跳出來 |

可讀性規則：

- 場地中央保持全場最亮；Boss 與玩家各帶一盞低強度的跟隨光，讓剪影和背景分開。
- 地面預兆 Decal 與落雷預兆改用發光色，雨夜裡也一眼看得到。
- 環境閃電不能和落雷招式的預兆同時出現，避免玩家誤判。

開場演出從「陰沉細雨」開始，OIIA 貓登場時轉成全面暴風雨（雨勢、風力、閃電頻率一起拉高），取代原本平靜到暴風雨的兩組天空。魔法陣 Decal 與 `ScaleRef_2m` 不動。

## 風險與對策

最大的風險是有機角色：腳本建模在建築、植被、道具上很穩，但貓、狗這種「要可愛」的造型最容易卡住，所以排程上先用環境定風格，角色再拿草稿與參考體積去打。

| 風險 | 徵兆 | 對策 |
| --- | --- | --- |
| 角色造型不像、不可愛 | 剪影迭代 3 次還不對 | 補更清楚的草稿；用 Hunyuan3D 體積＋Shrinkwrap；或由你在 Blender 推點，Claude 負責上色、拆件、匯出 |
| 暗林裡看不清招式 | 測試時常被沒注意到的攻擊打中 | 第 8 節的可讀性規則：場地中央最亮、角色帶跟隨光、發光預兆、環境閃電不和落雷預兆重疊；Phase 7 驗收時打一場完整戰鬥 |
| 模型被 Builder 覆寫 | 重跑 Builder 後模型消失 | Phase 0 先做 `ArtLibrary`，Builder 永不寫入 `Assets/Art/` |
| 部件與程序動畫對不上 | 換上新模型後動作歪掉、部件亂轉 | Phase 0 的接口規格；自動檢查比對名稱與軸心 |
| 後做的資產風格漂移 | 新舊資產放一起不協調 | 全部共用 `lowpoly_kit.py` 與色票；每階段結束與風格切片同畫面比對 |
| 平面著色變平滑 | Unity 裡面的邊緣糊掉 | Normals = Import、匯出前三角化 |
| 色票滲色 | 遠看顏色混到隔壁格 | UV 縮到格中心、Point 濾鏡、關 mipmap |
| 植被、雨、霧拖慢幀率 | 序章、休息區或競技場掉幀 | GPU Instancing、靜態合批；草叢只在鏡頭附近加密；雨粒子只在鏡頭周圍生成 |
| token 消耗過快 | 一個資產用掉好幾個 session | 照第 5 節：一張合成圖驗證、腳本存檔、同類資產一次做完 |
| Blender 或 MCP 中斷 | 執行失敗、Blender 當掉 | 腳本可重跑；每個資產完成就存 `.blend` 並 commit |
